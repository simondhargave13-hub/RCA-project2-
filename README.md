PhishGuard – Phishing URL Detection
Project Overvie
PhishGuard is a machine learning project that detects potentially phishing URLs and distinguishes them from legitimate URLs.

The project uses URL-based features and a Logistic Regression model to classify URLs as either legitimate or phishing.

Problem Statement

Phishing websites are designed to trick users into sharing sensitive information such as passwords, banking details, and personal data.

This project aims to build a machine learning model that identifies potentially phishing URLs using basic URL characteristics.

Objectives

- Analyze and clean the URL dataset.
- Extract useful features from URLs.
- Train a machine learning classification model.
- Evaluate the model's performance.
- Predict whether a given URL is potentially phishing or legitimate.

Dataset

The project uses the "phishing_site_urls.csv" dataset.

The dataset contains two columns:

- "URL" – Website URL
- "Label" – Classification of the URL

Labels:

- "good" – Legitimate URL
- "bad" – Phishing URL

Dataset Preprocessing

- Checked missing values and duplicate records.
- Removed URLs with conflicting labels.
- Removed duplicate rows.
- Selected 5,000 legitimate URLs and 5,000 phishing URLs.
- Created a balanced dataset containing 10,000 URLs.

Features Extracted

The following features are extracted from each URL:

Feature| Description
URL Length| Total number of characters in the URL
Dot Count| Number of dots in the URL
Hyphen Count| Number of hyphens in the URL
HTTPS| Indicates whether the URL starts with HTTPS
Digit Count| Number of digits in the URL

Machine Learning Model

The project uses Logistic Regression for binary classification.

Two model versions are trained:

1. Logistic Regression using original features.
2. Logistic Regression using standardized features.

"StandardScaler" is used to scale the features before training the second model.

Project Workflow

1. Load the phishing URL dataset.
2. Perform data cleaning and preprocessing.
3. Create a balanced sample of legitimate and phishing URLs.
4. Extract URL-based features.
5. Convert labels into numerical values.
6. Split the dataset into training and testing sets.
7. Train the Logistic Regression model.
8. Evaluate model performance.
9. Save the trained model and scaler.
10. Test the model using new URLs.

Model Evaluation

The model is evaluated using:

- Accuracy
- Confusion Matrix
- Precision
- Recall
- F1-Score

The notebook also compares the performance of the original and scaled Logistic Regression models.

4. Update the dataset file path if required.
5. Run the notebook cells in order.

Sample Prediction

The trained model can predict whether a new URL is potentially phishing or likely legitimate.

Example URLs used for testing:

- "https://google.com"
- "http://example.com"

Limitations

- The model uses only basic URL-based features.
- It does not analyze website content or webpage behavior.
- Predictions are based on patterns learned from the dataset.
- The model may produce false positive or false negative predictions.

Note: This project is intended for educational purposes. It should not be used as the only method for determining whether a website is safe.

Conclusion

PhishGuard demonstrates how machine learning can be applied to phishing URL detection. It includes data preprocessing, feature extraction, model training, evaluation, and prediction using Logistic Regression.
